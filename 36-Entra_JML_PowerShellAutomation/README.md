# Scenario

An organization wants to automate common Joiner, Mover, and Leaver (JML) identity lifecycle tasks using Microsoft Entra ID and Microsoft Graph PowerShell.

Employee lifecycle information originates from an HR system which generates CSV files that contain employee information and approved access requests.

Before creating an account, the automation validates employee-specific dependencies such as the manager, department mapping, and requested access.

If an unexpected failure occurs after account creation, the automation rolls back the newly created account and records the employee for retry.

The lab focuses first on the **Joiner** process. Mover and Leaver workflows may be added later.

---

# Requirements

The Joiner automation must:

- Process multiple employee records from a CSV file
- Generate usernames automatically
  - Naming convention: First two letters of the first name followed by the family name
- Detect username collisions and generate a unique UPN (collision test is described later)
- Prevent duplicate provisioning using **EmployeeId**
- Assign standard access based on department
- Process additional approved application access
- Verify required groups and manager
- Continue processing unaffected employees when one record fails
- Roll back a newly created account if provisioning fails partway through
- Produce operational results and retry files for failed records

# Part 1 - Prepare the Joiner Test Environment

### 1. Base structure

In this test, the lab tenant already contains the departmental structure and resources used by the JML workflow.

Objects created for the test are:
- Manager accounts
- Security groups
- Microsoft 365 groups

The Joiner workflow distinguishes between standard organizational access and individually requested access.
- Standard access is derived automatically from the employee's organizational information.
- Additional access is supplied through the RequestedAccess field in the source data.

For example, a Sales user receives:

- **Standard access**
  - Organization-wide security groups
  - Sales department groups
  - Organization-wide license groups
  - Sales license groups
- **Additional access**
  - Approved application access supplied through **RequestedAccess**

### 3. HR Joiner input

The Joiner batch contains 30 employees across five departments and the source CSV uses the following schema:

EmployeeId,FirstName,LastName,Department,JobTitle,ManagerUPN,StartDate,PersonalEmail,UsageLocation,RequestedAccess,Action

[The source CSV link](https://github.com/YK7188/YK_Lab/blob/main/36-Entra_JML_PowerShellAutomation/JML_Input.csv)

- Technical identity values such as the UPN are generated by the automation rather than supplied by HR.
- EmployeeId provides a stable employee identifier and is used to prevent the same employee from being provisioned more than once.
- RequestedAccess contains zero or more approved additional resources separated by semicolons.

# Part 2 - Run the Joiner Automation

[The automation script link
](https://github.com/YK7188/YK_Lab/blob/main/36-Entra_JML_PowerShellAutomation/Joiners.ps1)

Things below have been considered.

- Should one bad employee kill the batch?         No
- Should missing access be detected beforehand?   Yes
- Should HR supply the UPN?                       No
- How do we identify an employee reliably?        EmployeeId
- What happens on a UPN collision?                Increment suffix
- What happens after partial provisioning?        Rollback
- What happens to failed records?                 Retry CSV
- Should licenses be directly assigned?           No, group-based
- What happens after a department rename?         Pre-check failure

The script completes successfully, with all 30 accounts provisioned.
